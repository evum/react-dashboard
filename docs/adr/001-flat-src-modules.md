# 001. Плоские модули `src/` вместо FSD

- Статус: принято
- Дата: 2026-09-16

## Контекст

Нужно разложить React-дашборд: дерево, таблица, API. Типичное предложение агента — Feature-Sliced Design (слои `app` / `pages` / `widgets` / `features` / `entities` / `shared`) в упрощённом виде.

В проекте два экрана на одной странице, один тип сущности, нет маршрутов и дизайн-системы на несколько продуктов.

## Решение

Плоская нарезка по виду и роли:

```
src/App.tsx
src/Dashboard.tsx
src/Tree/
src/Table/
src/api/
```

Алиас `@/` → `src/`. Общие типы дерева живут в `src/api/utils.ts` — это контракт сервера, не «entity slice».

## Альтернативы

- **FSD lite** — предсказуемо для большой команды, здесь даёт пустые слои `entities/organization` и `widgets/dashboard` без выигрыша в навигации.
- **Колокация по фиче** (`src/organization/{tree,table,api}`) — хуже разделяет «сеть» и «представление»; хуки Query всё равно общие для обоих виджетов.

## Последствия

- Новый файл кладётся рядом с соседями по UI, а не по слою FSD.
- Граница «данные / UI» всё равно есть: только `src/api` ходит в сеть.
- При появлении второго домена (не орг-дерево) структуру придётся пересмотреть; до тех пор FSD — лишняя цена.
