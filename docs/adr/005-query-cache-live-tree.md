# 005. Живое дерево живёт в кэше React Query

- Статус: принято
- Дата: 2026-09-16

## Контекст

Снимок приходит через `useQuery`. Патчи должны обновлять то же дерево, которое читает `App`, без второго источника (`useState` + ручной merge).

Нужно: смена `version`, structural sharing, полный сброс при `reset`, индикатор здоровья ленты отдельно от снимка.

## Решение

Ключ `['org-tree']` — единственная копия `OrganizationStructure` на клиенте.

Лента `['org-tree-changes']` в `queryFn`:

1. читает снимок из кэша
2. качает патч с `since = structure.version`
3. `reset` → `invalidateQueries(['org-tree'])`
4. иначе `setQueryData(['org-tree'], applyOrganizationChanges(...))`
5. в кэш ленты кладётся только `changes.version` (для статуса, не для UI дерева)

`patchNodes` копирует узел только если он или дети изменились.

## Альтернативы

- **`useState` дерева в `App` + эффект поллинга** — дублирует кэш Query, сложнее retry/backoff.
- **Нормализация в `Map<id, node>`** — дешёвый патч по id, но дереву всё равно нужна сборка children; для размера мока лишнее.
- **Immer / reducer** — удобный merge, ещё одна зависимость при уже написанном рекурсивном `patchNodes`.

## Последствия

- Подписчики `useOrganizationStructure` обновляются сами.
- Гонка: лента не стартует осмысленно без снимка (`if (!structure) return null`).
- `staleTime` снимка 5 с не мешает патчам: они пишут в кэш напрямую, не ждут рефетча.
- Ошибка ленты не сбрасывает уже показанное дерево; статус в шапке переходит в «Переподключение…».
