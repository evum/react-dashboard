# 003. Сводка таблицы считается на клиенте

- Статус: принято
- Дата: 2026-09-16

## Контекст

Дерево отдаёт собственные метрики узла. Таблица должна показывать численность, бюджет и эффективность **поддерева**.

Считать можно на сервере (отдельный endpoint или поля в узле) или на клиенте при каждом снимке/патче.

## Решение

Чистая функция `convertToTableRows` в `src/Table/convertToTableRows.ts`. `TableComponent` вызывает её в `useMemo(..., [data])`. API и кэш хранят только `OrganizationNode[]`.

Тесты агрегации — unit на функцию, без React.

## Альтернативы

- **Сервер кладёт `total*` в каждый узел** — меньше работы на клиенте, но патч листа обязан пересчитывать всех предков на сервере, а дерево и таблица начинают расходиться в семантике полей.
- **Считать в рендере `TreeNode` / ячейки** — дублирование, сложнее мемоизировать, тяжелее тестировать.
- **Отдельный селектор в Query** (`select`) — привязка сводки к библиотеке кэша; таблица всё равно фильтрует и сортирует локально.

## Последствия

- Патч меняет только собственные поля; итоги предков появляются сами при следующем `convertToTableRows`.
- Стоимость — полный обход дерева на каждый патч. Для текущего мока это дёшево; при очень большом дереве понадобится инкрементальная агрегация.
- Дерево и таблица могут показывать разные числа по одному `id` — это намеренно (свой vs сводный).
