# 006. Эффективность родителя — среднее, взвешенное по headcount

- Статус: принято
- Дата: 2026-09-16

## Контекст

У каждого узла есть `performance` (0–100) и `headcount`. Сводка отдела/дивизиона не должна быть ни сырым KPI узла, ни средним арифметическим по трём командам разного размера.

Бюджет и численность однозначно суммируются. Для KPI нужен выбор.

## Решение

```
avg = Σ (performance_i × headcount_i) / Σ headcount_i
```

по всему поддереву, включая собственный `headcount` узла. Если сумма людей = 0, среднее = 0 (не NaN, не KPI «пустого» узла).

## Альтернативы

- **Сырое `node.performance` в таблице** — тогда таблица не агрегирует KPI и расходится с суммами людей/бюджета.
- **Среднее по узлам без весов** — команда из 3 человек равна отделу из 40.
- **Максимум / минимум по поддереву** — полезно для алертов, не для «средней эффективности».
- **Вес по бюджету** — другая бизнес-семантика; в ТЗ метрика привязана к людям.

## Последствия

- Патч численности листа двигает среднее всех предков даже при том же KPI листа.
- Отрицательный headcount парсер не запрещает (только `Number.isFinite`); мок держит `>= 1` для живых узлов.
- Отображение округляет процент в UI (`Math.round`); в строке таблицы хранится float.
