# 004. Раскрытые узлы — один `Set` в `Dashboard`

- Статус: принято
- Дата: 2026-09-16

## Контекст

Дерево сворачивается по узлам. Выбор строки в таблице должен раскрыть предков и прокрутить до узла. На мобиле вид «дерево / таблица» переключается, состояние раскрытия не должно сбрасываться.

Локальный `useState` в каждом `TreeNode` (`expanded: boolean`) — первый наивный вариант.

## Решение

`Dashboard` владеет `expandedIds: Set<string>`.

- старт: `collectExpandedIds(data)` — раскрыть до глубины 2 (дивизион и отдел)
- клик в дереве: `onToggle` добавляет/удаляет `id`
- выбор в таблице: `getAncestorIds(data, id)` дописывается в сет, вид переключается на дерево

`TreeNode` только читает `expandedIds.has(node.id)` и зовёт `onToggle`. Анимация высоты — в `Expandable`, не в состоянии.

## Альтернативы

- **Состояние в узле** — простое раскрытие, но таблица не знает, кого открыть; при смене `data` по ссылке узлы размонтируются и схлопываются.
- **Ключ вида `expanded:${id}` в URL** — шарибельно, избыточно для дашборда без роутера.
- **Раскрывать всех потомков выбранного** — шумно; достаточно предков, чтобы узел появился в кадре.

## Последствия

- Патч метрик не сбрасывает раскрытие: `id` стабильны, сет живёт в `Dashboard`, не в дереве данных.
- Сет не синхронизируется с исчезнувшими `id` (мок структуру не режет). Если появятся удаления узлов, понадобится чистка.
- `Set` в `useState` обновляется через новый экземпляр (`new Set(current)`), иначе React не увидит мутацию.
